# Quality harness reference

## Guardrails

Each guardrail is a toggle in `answers.json` under `guardrails`. All default to `true` (enabled). A disabled guardrail is never installed — its script, config, and CI step are omitted entirely.

### `eslintSeverityStaging`
Installs ESLint with a flat config (`eslint.config.mjs`). Rules use two tiers: errors block CI immediately; warnings form a tracked backlog. Promote a rule from `warn` to `error` once all its instances reach zero. This staging model lets brownfield projects adopt linting incrementally without blocking CI on day one.

### `locGuard`
Installs a per-file LOC ratchet (`scripts/check-loc.mjs`). Files exceeding `locCap` (default 500 lines) fail CI. The baseline snapshots the current maximum so no existing file is immediately red. New files must stay under the cap.

### `fallowRatchet`
Installs the fallow metric ratchet (`scripts/check-quality.mjs`). fallow measures dead code, duplication, and complexity (CRAP score). The baseline records today's counts; CI fails if any metric regresses. **Critical caveat:** always run `check:quality` with `./coverage` absent. A stale coverage artifact causes fallow to compute dynamic CRAP instead of static-estimated CRAP, inflating critical-complexity counts and producing false positives.

### `coverageFloors`
Installs coverage thresholds in the test framework config. The baseline runs `test:coverage`, measures the current summary, and floors each metric (statements/branches/functions/lines) at `Math.floor(pct)` — rise-only. If the test config is user-authored (no "Generated by project-setup" marker), the engine warns rather than rewriting it, and the floor is not set.

### `ci`
Requires `github.integrate: true`. Writes `.github/workflows/ci.yml` with steps for each enabled guardrail. Uses the detected package manager (npm/pnpm/yarn). In Obsidian mode the workflow also runs `check:css`, `typecheck`, `format:check`, `build`, and `check:artifacts`.

### `cssGuard` (Obsidian mode only)
Installs the CSS `!important` ratchet (`scripts/check-css-important.mjs`): scans `src/**/*.css` plus SFC `<style>` blocks, baselines current counts, and fails any new or grown use. Mirrors the marketplace validator's CSS finding.

## Ratchet + severity-staging mechanics

- **Fallow ratchet:** Snapshots are stored in `scripts/quality-baseline.json`. Each `check:quality` run compares current counts against the snapshot. Any regression (increase) fails. To tighten the ratchet, run `node scripts/check-quality.mjs --update` after improving the code.
- **LOC ratchet:** Snapshot is a per-file map (in `scripts/loc-baseline.json`) of every file currently over `locCap`. Each `check:loc` run fails any *new* file over the cap, or any grandfathered file that grew past its own recorded baseline (existing oversized files may shrink but not grow).
- **Coverage floor:** Stored as thresholds in the test framework config itself. Jest enforces them on every `test:coverage` run.

## `answers.json` shape (options object)

```json
{
  "testFramework": "jest",
  "locCap": 500,
  "packageManager": "npm",
  "guardrails": {
    "eslintSeverityStaging": true,
    "locGuard": true,
    "fallowRatchet": true,
    "coverageFloors": true,
    "ci": true,
    "cssGuard": true
  },
  "docs": {
    "scaffold": true
  },
  "github": {
    "integrate": false,
    "mcp": false
  },
  "hooks": {
    "sessionStart": false,
    "qualityGate": false,
    "preCommit": false
  },
  "obsidian": null,
  "prds": []
}
```

`testFramework` defaults to the detected framework (jest or vitest). `packageManager` defaults to the detected one. All guardrails default to `true` when omitted (`cssGuard` only takes effect in Obsidian mode). `hooks` are Obsidian-only and **default all `false`** — nothing installs a Claude Code hook unless asked (see `references/obsidian-plugin.md`).

## `prds` — product-vision questionnaire (`docs/prds/`)

Optional. Each entry is authored via the SKILL.md product-vision questionnaire and rendered to `docs/prds/<id>-<slug>.md` (YAML frontmatter + markdown), plus a `docs/prds/README.md` index. `prd-000` is the product vision; number features from `prd-001`. Files are `skip-if-exists`, so a re-apply never overwrites edits. Mode-agnostic — works for a plain repo and Obsidian mode alike.

```json
{
  "prds": [
    {
      "id": "prd-000",
      "title": "Product Vision",
      "status": "draft",
      "created": "2026-07-18",
      "problem": "The pain the product removes.",
      "vision": "The intended solution in a sentence or two.",
      "goals": ["Outcome 1", "Outcome 2"],
      "notes": "Optional extra context."
    }
  ]
}
```

Every field is coerced to a safe primitive: `id` is forced to `prd-<digits>` (auto-numbered by position when absent), `title` falls back to `Product Vision` (first) / `Untitled`, `status` to `draft`. `title` is JSON-encoded into frontmatter and its slug is stripped to `[a-z0-9-]`, so a crafted title can't break the YAML or escape `docs/prds/`. Empty `problem`/`vision`/`goals`/`notes` render as `_TBD._`.

`obsidian` is `null` for a plain JS/TS repo. Set it to an object to switch on the Obsidian-plugin harness — shape, defaults, and everything it generates are documented in `references/obsidian-plugin.md`. Obsidian mode forces `testFramework: "vitest"` and `typescript: true`.

Dependency versions come from `scripts/pins.json` (exact pins). `node setup.mjs refresh-pins` updates every pin to its latest release, keeping `typescript` within typescript-eslint's declared peer range.
