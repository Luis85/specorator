Agent Sidepanel

A Cursor-like AI writing assistant embedded in Obsidian's right sidebar — scoped to software spec writing, with trust-first design at every step.

User Goal · Increment 1

Have an AI chat available inside Obsidian on which I can pull files from my vault as context, ask questions, and get answers grounded in my actual notes.

Design Principles

How the agent is designed to behave

Three principles that govern every interaction pattern and UI decision.

1

Trust-first

The agent confirms before every file write, commit, or PR. Nothing happens without explicit user approval.

2

Transparent

Streaming step logs show exactly what the agent is doing. No black-box generation.

3

Scoped

The agent is focused on one feature at a time. Context is explicit and user-controlled.

Settings

What users can configure

Settings persist to localStorage. Two sections: Autonomy (how often the agent asks for approval) and Vault Browser (which folders are visible).

Autonomy level

Supervised

Confirms before every action — writes, commits, reads, generation triggers.

Assisted ← default

Confirms before file writes, commits, and PRs. Reads and searches run silently.

Autonomous

Acts without asking. Header hint updates to "Running without confirmation."

OQ-3 resolved: Autonomy is a single global dial, not per-action. Simplifies the mental model.

Engineering
Design Decisions

Key choices and rationale

Decisions made during this increment, captured for the engineering handoff.

ID Decision Rationale
D-01 Right sidebar, always visible Never occludes the editor. Obsidian convention. Agent is a persistent co-pilot, not a modal interruption.
D-02 Chat tab + Context tab only (MVP) Cleanest surface for increment 1. Tasks and Session add complexity only justified once the core chat loop is validated.
D-03 Unified input container Textarea and action bar (Attach · @file · send) live inside a single rounded container, matching Claude.ai's pattern. Reduces visual noise vs. separate toolbar row.
D-04 onMouseDown (not onClick) for popups Prevents textarea blur when user clicks @-mention results. Standard autocomplete pattern — textarea stays focused throughout selection.
D-05 File cards in chat thread When a file is added to context, a card appears inline in the conversation. Creates an audit trail of what context was loaded and when.
D-06 Global autonomy dial OQ-3 resolved. Single global setting is simpler than per-action toggles. Power users can switch to Autonomous; cautious users stay Supervised. Assisted is the safe default.
D-07 Vault folder filter in Settings Large vaults create noise in @ search and vault browser. Filter reduces cognitive load. Files already in context are not affected by toggling folders off.
D-08 Markdown rendering in agent messages Agent responses reference file names, use numbered lists for next steps, and inline code for slash commands. Rendering these makes responses scannable.
Open Questions

Outstanding decisions

Status of all OQs raised during design.

OQ-1
Should the agent auto-detect feature scope from the active Obsidian file?
Yes — the agent should read the currently open note and infer the feature context automatically. No manual scope selection needed.
✓ Resolved
OQ-2
How do we handle context drift across long sessions?
Proposal needed. Candidates: (a) session-scoped context that resets on panel reopen, (b) persistent context with a staleness indicator, (c) explicit "new session" action that clears context. This will be designed in the Session increment.
Proposal needed
OQ-3
Autonomy dial — per-action granularity or single global setting?
Global. Three levels: Supervised · Assisted · Autonomous. Simpler mental model. Per-action granularity can be added later if needed.
✓ Resolved
Next Steps

Increment roadmap

What follows this increment, in priority order.

2

Generation + streaming step log

Real Claude API integration. Streaming step log (pending → active → done rows) replaces the typing indicator for multi-step generation. Redirect and Stop controls. Intent preview card before vault writes.

3

Tasks + Session tabs

Background task queue with dependency tracking. Session timeline with undo window. Export session summary to vault. Context drift strategy (OQ-2) designed here.

4

Slash command palette + approval flows

/gen-prd · /gen-issue · /review · /triage etc. Approval card for vault writes and commits. PR lifecycle card (Draft → Review requested → Merged).

5

Stage tracker + lifecycle gate

Init → Spec → Review → PR → Done tracker. Gate review with pass/fail criteria. Stage-aware hint cards. Auto-advance on PRD approval.
