Section 01

Left Sidebar

The left sidebar is the workspace navigator. It provides immediate access to AI-driven actions, a list of recent issues, and an overview of open pull requests. It is intentionally narrow and dense — designed for quick scanning and single-click navigation, not detailed reading.

Section 02

Main View

The main view is the primary reading and working surface. It occupies the center column and adapts its content to four distinct states: Issue Workspace, PR Detail, Task Detail, and Activity Feed. Each state has a consistent structural grammar — eyebrow, title, meta, body — borrowed from editorial design to create a readable, information-dense layout without visual noise.

Topbar & Actbar
Topbar (Breadcrumb) Navigation
PurposeShows the current location as a breadcrumb trail. Single crumb for top-level views (issue, PR, activity). Two-crumb trail for nested views (issue › task, issue › PR).
InteractivityNon-terminal crumbs are clickable and navigate up the hierarchy. Terminal crumb is styled in --t0 and is non-interactive.
Dynamic labelReads from S.issueId / S.prId / S.taskId at render time. No hardcoded strings.
Parent crumb navigates up Terminal crumb is non-interactive
Action Bar (Actbar) Contextual Actions
VisibilityShown on Issue and PR views. Hidden on Task Detail and Activity Feed. Uses hidden class toggled by renderMain().
Issue actions✦ Triage Issue · ⊕ Break Down Issue · ⊙ Create PR · ✎ Edit Issue
PR actions✦ Triage PR (surfacing refinement gaps)
Button hierarchyPrimary AI actions use colored tints (purple = triage, teal = breakdown). Secondary actions use ghost style. Right side shows a contextual hint string.
Triage queues AI backlog task Breakdown shows/dismisses card Create PR injects into sidebar Edit Issue opens pre-filled modal

Section 03

Right Sidebar

The right sidebar is a contextual action panel. It adapts entirely based on what is active in the main view: a task list and AI prompt when on an issue, an agent chat log when a task is selected, and a dedicated PR action panel when a pull request is open. It is the operational layer of the interface — where things get done, reviewed, and moved forward.

Tasks Panel (default — Issue view)
Panel Header Labeled Buttons
Layout"TASKS" uppercase label on the left. Two labeled pill buttons on the right: ◉ Agents (green) and + Add Task.
Agents buttonTeal-green accent. Navigates directly to the Agents panel. Makes agent status discoverable without requiring a task click.
Add Task buttonToggles the quick-add form below the header. Closes on second click, Esc, or successful submit.
Agents → switches to Agents panel Add Task → toggles quick-add form
Quick-Add Task Form Inline Creation
Trigger+ Add Task button in panel header. Animates in with fadeOverlay. Input auto-focuses on open.
SubmitEnter key or Add button. Creates task with scope: 'issue', appended to Up Next. Shows toast. Updates issue progress bar.
Cancel✕ button or Esc key. Clears input and hides form.
Enter → creates task, re-renders list Esc / ✕ → hides form
Task List Scrollable
SectionsIssue tasks grouped under "Issue #N" label (blue-tinted), then Backlog tasks. "View all (61)" at the bottom links to the full backlog.
Row layoutCheckbox (done = green, others = grey ring) · label (strikethrough when done) · status dot · estimate · ◉ agent indicator if assigned.
NavigationClick navigates to task detail in main view and switches right panel to Agents panel.
Row click → Task Detail + Agents panel

PR Panel (active when a PR is selected)
⊙
The PR panel has no header bar — the topbar breadcrumb and sidebar active state already communicate context. The panel scrolls directly through its functional sections: Linked Issues, CI Checks, Review & Merge.
Linked Issues Conditional
VisibilityOnly shown if pr.issueIds.length > 0. Omitted entirely for PRs with no linked issue.
Row content⊙ icon · Issue number · truncated title · status dot (Open = green). Clicking navigates to the linked issue workspace.
Row click → Issue workspace
CI Checks Collapsible
Default stateCollapsed. Header shows a live summary: ✓ 4/4 passing (green) / ✕ N failing (red) / ○ N pending (amber). › chevron flips to ▾ when expanded.
Expanded viewIndividual check rows with ✓/✕/○ icon, check name, and status text. Each row clickable — shows a contextual toast with pass/fail detail.
RationaleCollapsed by default to keep the most actionable section (Review & Merge) immediately visible without scrolling.
Header click → expand/collapse Check row → status detail toast
Review & Merge Gated Workflow Merge gated by Approve
Unified sectionReview and Merge are a single section because they represent one continuous workflow step: review the code, then commit it. Separating them was misleading.
Review statusIcon + label for current review state (◎ Review required, ✓ Approved, ◐ Draft, ⊛ Merged). Color-coded.
Approve buttonVisible when reviewStatus !== 'approved' and PR is not a draft. On click: updates pr.reviewStatus, re-renders panel, unlocks merge.
Merge gateMerge button only appears after Approve is clicked. Before approval: shows dimmed "Approve this PR to unlock merge". Prevents accidental unreviewed merges.
Merge buttonFull-width purple. Enabled only when pr.checks === 'passing'. On click: 800ms delay, updates PR to merged, re-renders sidebar and main, updates PR row pill in sidebar.
Draft stateShows "◐ Mark as Ready" button instead. Converts draft to open on click, re-renders both panels.
Approve → unlocks merge, re-renders Merge gated behind approval Merge → 800ms delay, updates state Mark as Ready → converts draft
PR opened → Review required state
Approve clicked → reviewStatus = 'approved', merge unlocked
CI passes → Merge button becomes active
Merge clicked → status = 'merged', sidebar pill → purple ✓
