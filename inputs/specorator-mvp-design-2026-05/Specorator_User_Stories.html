Section 01

Left Sidebar

Navigation and workspace-level actions. The sidebar must let any persona reach any part of the workspace in a single click and initiate AI-driven actions without losing their current context.

Actions 4 stories
US-001 View the global activity log
HighLeft Sidebar
As a PM, I want to open a chronological log of all workspace events in a single click, so that I can understand what every agent did without navigating into individual issues.
Acceptance Criteria
✓Clicking "◎ Activity Feed" replaces the main view with the feed without losing sidebar state.
✓Events are grouped by day (Today / Yesterday / N days ago) in reverse chronological order.
✓Each event shows: icon, description, source (Issue #N or PR #N), and relative timestamp.
✓Clicking any event row navigates to the referenced issue or PR.
✓The badge count on the button reflects the total number of recent events.
US-002 Triage issues or PRs with a single click
HighLeft Sidebar
As a PM, I want to trigger an AI triage pass over the issue or PR backlog without leaving my current view, so that the AI handles prioritisation while I stay focused on current work.
Acceptance Criteria
✓"Triage Issues" and "Triage Pull Requests" each create a backlog task visible in the right panel.
✓A toast confirms the triage task was queued immediately on click.
✓The main view does not navigate away or change.
✓Badge counts on the buttons reflect the number of items awaiting triage.
US-003 Create a new issue from the sidebar
HighLeft Sidebar
As a Developer, I want to open a structured issue creation form without navigating away from my current context, so that I can capture a new requirement or bug report immediately when it occurs to me.
Acceptance Criteria
✓Clicking "New Issue" opens a modal overlay with: Title, Type, Scope, Description, and optional Agent assignment.
✓Title is required — form validates and focuses the field on empty submit attempt.
✓On successful creation, the new issue row is injected at the top of the Recent list in the sidebar.
✓A toast confirms the issue number assigned.
✓Clicking outside the modal or Cancel dismisses without creating anything.
US-004 Dismiss or suppress the actions sidebar section
LowLeft Sidebar
As a Developer, I want to collapse the Actions section when I'm not using AI-driven features, so that more space is available for browsing issues and PRs.
Acceptance Criteria
✓Clicking the "Actions" section label toggles the action rows with a smooth height animation.
✓Collapsed state persists within the session.
Issue Navigation 5 stories
US-005 Navigate to any issue with a single click
HighLeft Sidebar
As a Developer, I want to click any issue row and immediately see its full workspace in the main view, so that I can switch context between tasks instantly.
Acceptance Criteria
✓Clicking a row loads the correct issue workspace — the content varies based on the issue's type, scope, and task state.
✓The clicked row becomes active: left blue border, highlighted background, trailing → arrow.
✓Any previously active issue or PR row is deactivated.
✓The topbar breadcrumb updates to reflect the new issue title.
✓Active state is maintained when navigating back from task detail or PR detail.
US-006 Collapse the Issues section to reduce visual noise
MediumLeft Sidebar
As a Developer, I want to collapse the Issues list when I'm focused on pull request review, so that the PR list has more vertical space.
Acceptance Criteria
✓Clicking the "Issues ▾" heading collapses all issue rows with a smooth max-height animation.
✓Chevron flips ▾ → › when collapsed.
✓Re-clicking expands back. No content is lost.
US-007 See issue type at a glance from the sidebar
MediumLeft Sidebar
As a PM, I want to distinguish issue types visually without reading the full title, so that I can quickly scan for specific categories like bugs or research tasks.
Acceptance Criteria
✓Each row shows a color-coded avatar circle with a letter initial (F = feat, R = research/req, U = ui, etc.).
✓Colors are consistent and distinct: feat = purple, research = teal, fix = red, ui = rose, req = blue.
US-008 Filter issues to those I created or am assigned
MediumLeft Sidebar
As a Developer, I want to quickly filter the issue list to just "My Issues" or "Created Issues", so that I can find my own work without scrolling the full list.
Acceptance Criteria
✓Clicking "My Issues" or "Created Issues" applies the filter (currently shows a toast; full filter in production).
✓Active filter state is visually indicated.
US-009 See the issue number without opening it
LowLeft Sidebar
As a Developer, I want to see each issue's number directly in the sidebar row, so that I can reference it in conversation or copy it quickly.
Acceptance Criteria
✓Issue number is shown in monospace font between the avatar and the title.
✓Number is muted (--t2) so it doesn't compete with the title.
Pull Requests 3 stories
US-010 See all open PRs and navigate to any one
HighLeft Sidebar
As a Developer, I want to see a compact list of all open pull requests and open any one in the main view, so that I can review and merge PRs without leaving the workspace.
Acceptance Criteria
✓PR list is accessible via the "Pull Requests ›" heading. Starts collapsed; expands on click.
✓Each row shows: status icon (● open, ◐ draft, ✓ merged) · number · truncated title · colored dot.
✓Clicking a row loads the PR Detail in main and the PR Action panel in the right sidebar simultaneously.
✓Merged PRs remain visible with purple ✓ indicator.
US-011 Distinguish draft PRs from open PRs at a glance
MediumLeft Sidebar
As a PM, I want draft PRs to be clearly differentiated from open PRs in the sidebar, so that I don't accidentally try to review or merge unfinished work.
Acceptance Criteria
✓Draft PRs show ◐ (half-filled) in amber. Open PRs show ● in green. Merged show ✓ in purple.
✓The colored dot on the right of each row matches the status color.
US-012 See newly created PRs appear in the list immediately
MediumLeft Sidebar
As a Developer, I want a PR I create via "Create PR" to appear at the top of the sidebar PR list immediately, so that I can track its progress without a manual refresh.
Acceptance Criteria
✓New PR row is prepended to the PR list within ~700ms of clicking "Create PR".
✓Row shows ◐ draft state in amber, with the correct title and number.
Section 02

Main View

The primary workspace. Four distinct states — Issue Workspace, PR Detail, Task Detail, Activity Feed — each with a consistent editorial structure. The main view must communicate both the current state and allow action without requiring the user to navigate away unnecessarily.

Topbar & Actbar 3 stories
US-013 Always know where I am in the workspace
HighMain View
As any user, I want a clear breadcrumb showing my current location at all times, so that I never feel lost when navigating between issues, tasks, and PRs.
Acceptance Criteria
✓Topbar always shows the current view title, derived dynamically from state (no hardcoded strings).
✓Nested views (task detail, PR from issue) show a two-crumb trail with a clickable parent.
✓Clicking a non-terminal crumb navigates up the hierarchy.
US-014 Trigger AI actions on the current issue from the actbar
HighMain View
As an Agent Supervisor, I want one-click access to Triage, Break Down, Create PR, and Edit Issue actions contextual to whichever issue I'm viewing, so that I can manage the work lifecycle without navigating to separate settings screens.
Acceptance Criteria
✓Actbar shows on Issue and PR views; hidden on Task Detail and Activity Feed.
✓Each button triggers its action without navigating away from the current view.
✓Buttons use consistent visual hierarchy: AI actions in colour, utility actions in ghost style.
US-015 Get an AI-generated breakdown of an issue into sub-tasks
HighMain View
As a PM, I want the AI to suggest a breakdown of the current issue into focused, independently shippable sub-tasks, so that I can assign granular work to agents without manually decomposing every issue.
Acceptance Criteria
✓Clicking ⊕ Break Down Issue shows a card prepended above the issue workspace after ~700ms.
✓Card shows numbered sub-task suggestions with labels, descriptions, and time estimates.
✓"Add as Tasks" appends suggestions to the Up Next section and auto-removes the card.
✓"Create Sub-Issues" queues sub-issue creation and shows a success message.
✓Clicking ⊕ again while card is open dismisses it (toggle behavior).
Issue Header & Context 3 stories
US-016 Read the full issue spec at the top of the workspace
HighMain View
As a Developer, I want to see the issue title, type, scope, status, description, and progress summary without scrolling, so that I can orient myself immediately when opening an issue.
Acceptance Criteria
✓Header shows: eyebrow (scope · type) · title · meta row · description · progress bar.
✓Progress bar accurately reflects the ratio of done tasks to total tasks.
✓Running agent count shown in green alongside the progress bar when agents are active.
US-017 Add acceptance criteria and context notes to an issue
HighMain View
As a PM, I want to attach additional context — acceptance criteria, technical constraints, related links — directly to an issue, so that agents and collaborators have the full picture when working on it.
Acceptance Criteria
✓When no context exists, a "⊕ Add context…" prompt is shown below the description.
✓Clicking the prompt (or "✎ Edit Issue" in actbar) opens the Edit modal pre-filled with current values.
✓Context field is a large textarea with placeholder guidance text.
✓On save, context appears as a persistent block below the description with an inline Edit shortcut.
✓Context survives navigation — persists in the ISSUE data object for the session.
US-018 Edit issue title, type, scope and description
MediumMain View
As a Developer, I want to correct or update any core field of an issue through a structured form, so that the issue remains accurate as requirements evolve.
Acceptance Criteria
✓Edit modal pre-fills all fields from current issue data.
✓Type and Scope use segmented selectors with clear visual selection state.
✓On save, the issue header re-renders immediately with updated content.
✓Title is required — save is blocked and field is highlighted if empty.

✓Accepted card becomes a dimmed stub showing "✓ Accepted" with the file path.
✓Toast confirms the acceptance.
✓The accepted file appears in the Related Files section.
US-021 Reject a proposal and remove it from review
MediumMain View
As an Agent Supervisor, I want to reject a proposal and have it cleanly removed from the review queue, so that the issue workspace stays clean and only shows actionable items.
Acceptance Criteria

✓A toast confirms the rejection.
✓Rejected proposals do not appear in the Related Files section.

US-025 See all files touched by an issue in one place
HighMain View
As a Developer, I want to see every file created, modified, or deleted across all PRs and proposals linked to an issue, so that I have a complete picture of the issue's footprint in the codebase.

US-026 Inspect the diff of any file from the issue workspace
MediumMain View
As a Developer, I want to open a line-by-line diff for any file in the issue's artifact list, so that I can verify what changed without switching to a separate code review tool.

Acceptance Criteria

✓Clicking the breadcrumb navigates back to the issue workspace.
✓Linked issue row in the right PR panel also navigates to the issue.

Section 03

Right Sidebar

The operational layer. The right sidebar switches between four modes depending on context: Tasks (issue open), Agents (task selected), Agent Chat (agent clicked), and PR Panel (PR open). It always ends with an AI input that is scoped to the current context.

Tasks Panel 4 stories
US-038 See all tasks for the current issue in the right panel
HighRight Sidebar
As a Developer, I want a persistent task list in the right panel while reading the issue workspace, so that I can track task status without scrolling down to the task sections in the main view.
Acceptance Criteria
✓Right panel shows the task list whenever the main view is on the Issue Workspace.
✓Issue tasks are grouped under a "Issue #N" sub-label. Backlog tasks below.
✓Each row shows: checkbox (done state) · label (strikethrough when done) · status dot · estimate · agent indicator.
US-039 Add a task quickly without opening a full form
HighRight Sidebar
As a Developer, I want to add a new task to the issue with a single click and a quick text entry, so that I can capture ad-hoc tasks without interrupting my reading flow.
Acceptance Criteria
✓"+ Add Task" button in the panel header toggles an inline form directly below the header.
✓Input auto-focuses on open. Enter submits. Esc or ✕ cancels.
✓New task is appended to the issue task list and appears immediately. Toast confirms.
✓Issue progress bar in the main view updates to reflect the new task.
US-040 Navigate to the Agents panel from the task list
MediumRight Sidebar
As an Agent Supervisor, I want a direct shortcut to the Agents panel from the task list header, so that I can check agent status without needing to click into a specific task first.
Acceptance Criteria
✓"◉ Agents" button in the task panel header switches the right panel to the Agents list.
✓Button uses green accent to signal live agent activity.
✓Back navigation from Agents panel returns to the Tasks panel.
US-041 Acknowledge there is more work without loading it all
LowRight Sidebar
As a PM, I want to see a "View all (N)" link that indicates there is a larger backlog without loading it all into the panel, so that the panel remains performant and focused.
Acceptance Criteria
✓"View all (61)" link is visible at the bottom of the task list.
✓Clicking it shows a contextual toast (full backlog view in production).
