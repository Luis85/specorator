> Part 3: [`2026-06-26-obsidian-marketplace-review-part3.md`](2026-06-26-obsidian-marketplace-review-part3.md)
> (this note reverses two of its decisions — see "Reversed part-3 decisions").

Two part-3 decisions taken for the Obsidian marketplace submission turned out to
be net-negative and were reversed on a single branch. This note records *why*,
and the exact surface that came back / went away.

## 1. `minAppVersion` reverted 1.13.0 → 1.11.5

Part 3 bumped `manifest.minAppVersion` 1.11.5 → **1.13.0** so the deprecated
button/slider/settings APIs (`setWarning`, `setDynamicTooltip`, `display()`)
type-checked against the newer `obsidian` typings and the marketplace bot would
stop flagging them.

**The problem:** 1.13.0 is unreleased. Obsidian *refuses to load* a plugin whose
`minAppVersion` exceeds the installed app version — so on every shipping desktop
(≤1.12.x) the plugin silently failed to load and the **entire Specorator settings
tab vanished**. A submission-cosmetics change broke the plugin for all current
users.

**The fix:** `minAppVersion` back to **1.11.5** (the SecretStorage floor — see root
`CLAUDE.md`), the `obsidian` devDep pinned to `~1.12.3` (allows 1.12 patches, not
1.13), and the three reverted call sites restored to their ≤1.12.x forms:

- `setDestructive` → `setWarning` (`dialogButtons.ts`, `VaultTrustModal.ts`,
  `AgentBoardLaneEditor.ts`)
- `.setDynamicTooltip()` re-added on the max-chat-tabs slider
  (`GeneralTabSections.ts`)
- the `refreshDisplay()` wrapper dropped; the four call sites call `this.display()`
  directly again (`SpecoratorSettings.ts`)

**Accepted consequence:** until 1.13 actually ships, the marketplace bot re-lists
`setWarning`, `setDynamicTooltip`, and `display` as **non-blocking** Warnings /
Recommendations. That is acceptable — they are advisory, not Errors, and the
declarative `getSettingDefinitions` API still can't express this plugin's
tabbed/searchable settings UI, so `display()` remains the supported render path
regardless. When 1.13 is GA, re-apply the migration *and* the `minAppVersion`
bump together (never the bump alone).

The non-version-coupled quality bits from the same original commit (`a14924c`)
were **kept**: the type-assertion generic rewrites, the `check:css` ratchet, and
`useUnknownInCatchVariables`.

## 2. User tool library dropped

Part 3 chose to **keep** the user-tool sandbox's `Function` constructor and
disclose it in the submission notes. The `Function` constructor
(`SpecoratorToolRegistry.ts:30`, used to evaluate transpiled user-authored
`.specorator/tools/*.ts`) was the **only blocking marketplace Error** in the
whole review — every other finding was a Warning or Recommendation.

Rather than ship one blocking Error behind a disclosure (and bet on the
reviewer's discretion), the feature was removed. Dynamic evaluation of user code
*was* the feature, so there was no in-place fix that kept it; the precedent
plugins (Dataview, Templater, QuickAdd, JS Engine) do the same thing but the
risk/benefit for *our* still-young feature didn't justify the one Error. It may
be revisited later (e.g. via a worker/iframe sandbox or a non-`eval` execution
model) — the design specs are kept as historical record, marked `superseded`.

### Exact surface removed

Code + tests (deleted in commit `28fbcfa`):

- Feature directory `src/features/tools/**` (10 files): `SpecoratorToolRegistry`,
  the in-process MCP tool server (`host/InProcessToolMcpServer.ts`), the local
  HTTP tool server (`host/SpecoratorHttpToolServer.ts`), `host/toolInvocation.ts`,
  `scopedTools.ts`, `toolRequestSignal.ts`, `toolTypes.ts`, `transpile.ts`, and
  the views (`view/ToolEditorModal.ts`, `view/ToolLibraryView.ts`).
- The mirrored `tests/unit/features/tools/**`.
- Wiring: `main.ts` imports/fields/view/ribbon/command/registry+HTTP init/teardown
  and the four `getSpecorator*Tool*` / `getHttpToolServerConfig` plugin methods;
  the optional `PluginContext` tool methods; the `toolLibrary:changed` event; the
  Tools entry in `libraryNav`.
- Bound-agent **tool grants** (distinct from provider subagent `tools` /
  `disallowedTools` frontmatter, which are untouched): the roster `tools` field
  across `rosterTypes`/`presetAgents`/`rosterCapabilities`/`AgentRosterStore`/
  `rosterAgentProjection`/`boundAgentPersona`, the Tools capability card in
  `AgentDetailEditor`, the `rosterDirty` comparison, the roster-card Tools badge,
  the `boundAgentTools` query-option, and the per-provider pass-throughs in the
  Claude / Opencode / Cursor runtimes.

i18n + styles + deps (this WS2-part-2 pass, commit on `2026-06-26`'s review
branch):

- i18n: the `toolLibrary.*` type union members and the `toolLibrary` locale block;
  `agentRoster.tools` / `noToolsHint` / `toolGrantScopeHint` / `searchTools`;
  `commands.openToolLibrary`; `ribbon.openToolLibrary` — removed from the type
  unions **and** all 10 locales (kept locale↔type parity). `agentRoster.capsSummary`
  was repurposed from `"{skills} skills · {tools} tools"` to a skills-only
  `"{skills} skills"` (the roster card had no Tools count to show). The unrelated
  `settings.subagents.modal.tools` (provider-subagent UI) was **kept**.
- Styles: the dead `data-type="specorator-tool-library"` header selector in
  `library.css` and the `.specorator-roster-tools-scope-hint` rule in
  `agent-roster.css`; shared `.specorator-library-*` / capability-picker rules kept.
- The `sucrase` runtime dependency (the tool transpiler) was removed from
  `package.json` — fallow flagged it as an unused dependency once the feature was
  gone, so it was deleted rather than baselined.

### Baselines

The deletion shrank the codebase: the LOC and CSS ratchets stayed green (they
allow shrinkage); the fallow quality ratchet's `complexFunctions` dropped 242 →
240 and the gain was locked into `scripts/quality-baseline.json`. Removing
`sucrase` cleared the one `deadCodeIssues` regression (back to 0).

## Reversed part-3 decisions

Both annotated in
[`2026-06-26-obsidian-marketplace-review-part3.md`](2026-06-26-obsidian-marketplace-review-part3.md):

1. **"API deprecations — FIXED via minAppVersion bump"** — reversed. The bump made
   the plugin unloadable on shipping Obsidian. Deprecations return as advisory
   findings until 1.13 ships.
2. **"Function constructor (Error) — KEPT + disclosed"** — reversed. The feature
   that needed it was removed, eliminating the only blocking Error.
